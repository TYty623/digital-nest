# 数字小窝：生命纪念馆核心体验 PRD

版本：1.0  
状态：已实现，待种子用户验证  
更新：2026-09-08

## 1. 产品定位

数字小窝不以“电子墓碑”或亲友协作作为主产品，而是一座由主人长期补充的宠物生命记忆馆：

> 记录 TA 怎样生活过，而不只是 TA 何时离开。

主人独自使用时必须成立；亲友留言只是附属能力。公开内容通过低互动、强策展的弱社区被看见，但不引入关注、私信、热度榜或付费祭品。

## 2. 本版核心体验

### 2.1 TA 的一天

- 主人按 `HH:mm` 记录一天中最多 12 个生活片段。
- 每个片段包含动作标题、熟悉位置、细节故事和一张可选相册照片。
- 关联照片必须属于当前主人，并已加入当前纪念页相册。
- 支持新增、编辑和删除；公开页按时间顺序展示。
- 公开页根据所选时刻呈现清晨、午后、黄昏、夜晚四种光线氛围。

### 2.2 生命指纹

固定记录十类真实细节：昵称、食物、位置、小习惯、害怕的事、会为什么跑来、喜欢黏着谁、熟悉声音、特别记号、教会主人的事。

- 每项最多 300 字，可单独保存或清空。
- 不生成性格结论，不使用 AI 虚构经历。
- “最有辨识度的小习惯”优先作为弱社区摘要。

### 2.3 记忆陈列馆

现有相册、声音记忆、旧物故事、回忆采访和纪念信继续保留，并与“TA 的一天”和生命指纹共同组成纪念空间。安葬与归处仍位于主人空间深处，默认私密，申请公开后人工审核。

### 2.4 今天想起这件小事

公开页每天从主人已填写的生活片段、生命指纹和回忆采访中稳定选择一条内容。该能力只重新呈现真实数据，不生成新的记忆，不设置签到或连续天数。

### 2.5 纪念星河（弱社区）

- 只有 `PUBLISHED + PUBLIC` 的纪念页进入列表。
- `PRIVATE`、`LINK`、`PASSWORD` 页面完全排除。
- 摘要只包含宠物昵称、类型、陪伴年份、封面、一句生活细节、公开时间和点灯数。
- 不返回主人姓名、邮箱、详细位置、信件、安葬信息或亲友留言。
- 支持按宠物类型筛选、按生活细节主题策展，以及无排行的“远方点灯”。

## 3. 创建流程修复

- 陪伴开始与结束日期都不能晚于本机今天，前端与后端规则一致。
- 结束日期不能早于开始日期。
- 日期错误在第一步就地显示；最终步提供“返回修改日期”。
- 最终步明确显示“尚未保存”，不再误报“小窝已经出现”。
- 保存成功后直接进入纪念小屋，继续填写核心内容。

## 4. 数据模型

Flyway `V25__add_life_portrait_and_day_moments.sql` 新增：

- `memorial_day_moments`：生活片段、可选相册媒体引用、创建与更新时间。
- `memorial_life_details`：受控键值生命细节，同一纪念页每个键唯一。

两表均通过 `memorial_id` 级联删除；生活片段的媒体删除后引用置空，文字记忆仍保留。

## 5. API

主人接口：

- `POST /api/v1/memorials/{id}/day-moments`
- `PUT /api/v1/memorials/{id}/day-moments/{momentId}`
- `DELETE /api/v1/memorials/{id}/day-moments/{momentId}`
- `PUT /api/v1/memorials/{id}/life-details/{detailKey}`
- `GET /api/v1/memorials/{id}/experience`

公开接口：

- `GET /api/v1/memorials/public/{slug}/experience`
- `GET /api/v1/memorials/public/discover?limit=24`

## 6. 权限与安全门禁

- 所有主人写接口必须验证纪念页所有权。
- 生活片段关联媒体同时验证媒体所有者、图片类型和当前相册归属。
- 生活时间由前后端共同验证，服务层仍保留信任边界校验。
- 社区使用专用最小公开投影，不复用包含完整纪念数据的主人响应。
- 公开摘要最长 90 字，避免卡片暴露过多私人叙述。
- 数据导出包含生活片段和生命指纹，用户可以完整带走新增内容。

## 7. 设计约定

**第一视觉对象**：宠物真实生活中的一个片段，而非模块菜单或离世日期。  
**主要动作**：添加“TA 的一天”生活片段。  
**交互模型**：时间轨道 + 生活场景；生命指纹使用可独立保存的事实条目。  
**响应式优先级**：手机端保留时间横向浏览，场景图片与文字改单列。  
**可更换性**：颜色、字体、圆角继续由设计令牌控制；数据接口不依赖页面主题。  
**禁止默认**：不使用排行榜、粉丝数、连续签到、虚拟币、付费香火和陌生人私信。

## 8. 成功指标

北极星指标：每月发生过一次主人主动回看、补充或纪念行为的有效纪念空间数量。

首轮种子验证指标：

| 指标 | 目标 |
|---|---:|
| 创建流程保存成功率 | ≥ 80% |
| 新建后 7 日内添加至少 3 个生活片段 | ≥ 35% |
| 新建后 7 日内填写至少 3 条生命指纹 | ≥ 40% |
| 公开纪念页 30 日主人回访率 | ≥ 25% |
| 纪念星河卡片进入完整纪念页的点击率 | ≥ 12% |
| 公开内容举报率 | ≤ 1% |

这些数字是验证目标，不是假定已有基线。上线前至少邀请 10 名种子用户完成真实任务测试。

### 8.1 情绪设计与回访机制

本版补充一条“不催促、不上瘾”的回访链路：

- 首页“记忆采样器”用动作、声音、位置和旧物四类具体问题降低第一次书写门槛；答案示例只展示叙事颗粒度，不代替用户生成记忆。
- “我的小窝”每日稳定重现一条用户已经写过的真实细节，并把用户带回对应纪念小屋；不使用签到、连续天数、限时奖励或焦虑提醒。
- 纪念小屋用六项“记忆轨迹”表达内容完整度，并只推荐当前最容易继续的一步。百分比用于帮助理解整理进度，不与其他用户比较，也不解锁付费权益。
- 公开页在切换“TA 的一天”时使用轻微场景过渡，访客点亮后只给一次柔和微光反馈；首页星光、月亮和小动物使用低频环境动效。
- 所有非必要动画在 `prefers-reduced-motion: reduce` 下关闭；内容和操作不依赖动画才能理解或完成。

建议额外观察三个行为指标：记忆采样器到创建页的进入率、“今天再回来一会儿”的点击率，以及回访后新增一条真实内容的完成率。它们用于判断产品是否帮助用户继续纪念，而不是衡量用户停留得是否足够久。

## 9. 本版非目标

- 不做宠物人格复活、声音克隆或以宠物身份回信。
- 不做精确墓地地图、线下殡葬撮合或交易。
- 不做陌生人关注、私信、评论信息流和热度排名。
- 不做自动推送和周期提醒；需要实际通知授权与用户研究后再立项。
- 不做真实 AI 纪念影片生成；本版优先验证结构化记忆是否有价值。

## 10. 发布结论

代码范围已完成，但正式上线仍受域名备案、运营主体、条款法务复核、生产对象存储、监控备份和真实用户验证约束。仓库内通过测试不等于这些外部条件已经满足。
