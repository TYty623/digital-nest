# 数字纪念与持续性联结：实现说明

## 已落地的产品边界

产品从单次展示型纪念页扩展为三层体验：保存真实生活痕迹、完成可选择的纪念仪式、在明确授权下整理数字记忆。

- 基础纪念、查看、亲友访问、导出和删除不受会员墙限制。
- 仪式没有金币、排行、连续打卡或强制分享；声音默认不播放。
- 社区继续采用自愿公开、审核和弱互动模式，不把私密生命档案带入推荐流。
- 数字生命不扮演逝去的生命，不宣称复活、灵魂或意识延续。

## 已实现的功能

### 仪式中心

`/editor/{id}/ritual` 提供四步流程：进入安静空间、回看一段可追溯记忆、选择纪念动作、收束并保存仪式记录。可选动作是点灯、纪念花、写信、声音和时间胶囊；记录默认只保存在所有者空间和年度纪念册。

### 生命档案

`/editor/{id}/archive` 支持地点、关系、旧物、瞬间和媒体五种档案。每条都带有来源、日期、可见范围和“已确认 / 待确认”状态。地点只保存说明文字，不接受门牌、联系方式或经纬度。

### 纪念日、时间胶囊与年度纪念册

- `/editor/{id}/calendar` 保存生日、相遇日、领养日、离开周年、四季和自定义日期。提醒默认关闭，当前只保存用户意愿，不会主动发送消息。
- 时间胶囊必须设为未来日期；免费空间可保存一封，高级会员可保存多封。
- `/editor/{id}/yearbook` 从生命档案、仪式和时间线生成年度预览。具备权益的用户可通过浏览器“打印 / 存为 PDF”。实体印刷只定义了 `YearbookPrintOrderPort`，尚未接入供应商、地址或支付。

### 会员权益

服务端通过 `BillingService.capabilitiesFor` 集中判断权益，前端只展示服务端返回的结果。权益码包括：

- `PREMIUM_RITUAL_THEME`
- `MEMORY_CAPSULE`
- `YEARBOOK_EXPORT`
- `EXTENDED_STORAGE`
- `DIGITAL_LIFE_PROFILE`
- `DIGITAL_LIFE_QA`
- `DIGITAL_LIFE_VOICE`
- `DIGITAL_LIFE_AVATAR`

`DIGITAL_LIFE_VOICE` 与 `DIGITAL_LIFE_AVATAR` 目前没有被授予任何套餐，页面会明确显示尚未开放。

### 数字生命的分阶段设计

`/editor/{id}/digital-life` 的第一阶段为数字记忆档案。用户必须分别确认资料整理与文本处理授权；生命指纹的自动导入条目全部标记为待确认。只有用户确认的资料会进入第二阶段问答。

当前问答是本地确定性模拟：只检索已确认事实、回答使用第三人称、附带来源，资料不足时明确回答不知道。没有调用任何外部模型或第三方服务。

为后续服务商接入预留了以下端口：

- `MemoryAnswerProvider`
- `VectorSearchProvider`
- `VoiceReplicaProvider`
- `AvatarProvider`
- `ContentModerationPort`

数字记忆档案可暂停、封存或永久删除。删除数字档案会级联删除其事实和授权记录；删除纪念页或账户时，数据库外键同样会级联删除所有新增数据。

## 安全设计

- 每个新接口都先校验当前账户对纪念页的所有权。
- 数字问答、档案和胶囊只可由所有者访问，不能通过公开纪念页读取。
- 对详细地址、联系方式、证件样式号码和经纬度做服务端校验。
- 自伤高风险文字不会在此类私密内容中静默保存，接口会给出支持提示。
- 外部声音与形象能力保持禁用，未来启用前必须增加单独的权利授权、审核、删除与供应商评估。

## ADR-001：以模块化单体承载新增领域

**状态：已采用**

当前团队和项目规模适合保持 Spring Boot 模块化单体。新增 `journey` 和 `digitallife` 模块分别承担仪式/档案与高敏感数字记忆领域，通过服务层调用现有纪念页和会员服务。这样保留了未来替换 AI、向量检索、声音和形象供应商的边界，同时避免现在拆分微服务造成的复杂度。

取舍：模块仍共享同一数据库和部署单元；当异步生成任务或内容审核吞吐量显著增长时，再将端口实现迁到独立工作进程。

## 尚未接入的能力

- 真实推送渠道和提醒调度
- 外部大模型、向量数据库、声音复刻和数字形象供应商
- 声音与形象权利审核流程
- 实体纪念册印刷、收货地址、物流和支付
- 生产上线前的个人信息、生成式 AI、声音肖像与内容安全合规评估
